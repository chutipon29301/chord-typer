<task type="checkpoint:human-verify" gate="blocking">
  <name>Task 1: Verify CGEventTap transparent pass-through and permission UX</name>
  <what-built>
    CGEventTap event interception pipeline: EventTapManager creates a session-level tap that intercepts keyDown/keyUp events and passes them through unchanged. AppDelegate manages the lifecycle, presents a permission alert if Accessibility permission is missing, and recovers from sleep/wake.
  </what-built>
  <how-to-verify>
    1. Run `make run` from the project root (this resets TCC and launches the app)
    2. **Permission flow (if Accessibility not yet granted):**
       - An NSAlert should appear saying "Accessibility Permission Required"
       - Click "Open System Settings" — System Settings should open to Privacy & Security > Accessibility
       - Grant ChordTyper permission in System Settings
       - Return to the app — within a few seconds the tap should auto-activate (check Console.app for "CGEventTap installed and running" log)
    3. **If Accessibility already granted:** The app should launch silently into the menubar with the tap active
    4. **Transparent pass-through verification:**
       - Open TextEdit and type "Hello world" — all characters should appear correctly
       - Open Terminal and type `ls -la` — command should execute normally
       - Open Safari and type in the URL bar — all keystrokes should appear
       - No characters should be missing, duplicated, or delayed
    5. **Console.app verification:**
       - Open Console.app, filter by "dev.chutipon.chordtyper"
       - Confirm you see "CGEventTap installed and running" log message
       - Type a few keys — no error or warning messages should appear
    6. **Quit verification:** Click the menubar icon > Quit ChordTyper — app should terminate cleanly
  </how-to-verify>
  <resume-signal>Type "approved" if keystrokes pass through transparently in all tested apps, or describe any issues observed</resume-signal>
</task>
